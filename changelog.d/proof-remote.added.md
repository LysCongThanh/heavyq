**Proofs run where heavy work goes.** `item done --run` and `gate run` no longer always run on this machine: set `[proof] remote = "local" | "auto" | "<remote name>"` in the user config or a repository's `heavyq.toml` (the default stays `local`), or pass `--remote` to either command. `auto` lets the scheduler choose among this machine and your remotes, free slots first. A run on a remote counts as proof for the same tree (the run identity never contained the machine, now pinned by a test); with uncommitted changes `auto` stays local and a named remote is refused, because a remote only runs committed code. See [docs/items.md](docs/items.md#where-the-proof-runs). (#115)
