**`item done` no longer conflicts when agents in parallel work trees finish adjacent items (#119).** In a repository with more than one work tree, `heavyq item done` proves the item, records it in the events log that every work tree shares, and leaves `.heavyq/anchor.md` untouched, so nothing about the anchor needs restoring or committing in a lane and two lanes' branches merge cleanly. The item reads done everywhere at once (`item ls`, `claim --next`, the stop gate); the new `heavyq item sync` ticks the boxes later, once, where the anchor is committed, one byte per box and idempotent. A claim by name takes back an item that is done only in the log. `[items] tick = "auto" | "always" | "never"` in `heavyq.toml` picks the behavior: `auto` (the default) ticks only in a repository of one work tree, `always` keeps the earlier behavior everywhere. See [docs/items.md](docs/items.md#parallel-work-trees-tick-and-sync).
