**`heavyq preflight` no longer says NO-GO for permission shapes it is unsure about.** The permission check now blocks only when it is sure (a deny or ask rule matches, or no allow rule can cover the command) and warns `may prompt` otherwise. It was checked against decisions recorded from a live headless Claude Code 2.1.316 (`internal/preflight/testdata/permission-corpus`), which fixed real mismatches: `Bash(x *)` also matches bare `x`; `CI=1`, `NODE_ENV=` and `timeout`/`time`/`nohup`/`nice`/bare `xargs` prefixes no longer make an allowed command block; `> file` redirections, `$( )` and a dangling `&&` are now caught. See [docs/preflight.md](docs/preflight.md).
