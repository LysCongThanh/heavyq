**The morning recap and `flow show` tell the truth about proofs that went stale, and count proofs nobody claimed first.** A ticked item whose proof passed on older code (any commit since, a docs-only one too) is now `done · stale` in `heavyq recap` (a bucket of its own, with `heavyq item done <id> --run` as the action) instead of "claimed, unproven", and `heavyq flow show` counts it as `done-stale` (`items.done_stale`, additive) instead of `open`; a stale item nobody ticked stays open work. Throughput counts every finished item in the window: an item that reads `proven`, a `done` event, or, for an item that reads `stale`, its gate passing in the ledger (every command the gate has on one tree), claimed or not, so a lead who proves items without claiming them no longer reads `0 proven/h`; an item still held or open is never finished by another lane's pass of a gate they share. The claim-to-proof median is now only the lead time (a claim paired with the first finish after it), and the forecast falls back to the measured rate when there is no median (`ETA = now + remaining ÷ proven/h`) instead of staying `unknown`.
