**The morning recap and `flow show` tell the truth about proofs that went stale, and count proofs nobody claimed first.** A ticked item whose proof passed on older code (any commit since, a docs-only one too) is now `done · stale` in `heavyq recap` (a bucket of its own, with `heavyq item done <id> --run` as the action) instead of "claimed, unproven", and `heavyq flow show` counts it as `done-stale` (`items.done_stale`, additive) instead of `open`; a stale item nobody ticked stays open work. Throughput counts every finished item in the window: a `done` event, or the item's gate passing in the ledger (every command on one tree), claimed or not, and whether or not the code has moved on since, so a lead who proves items without claiming them no longer reads `0 proven/h`. The claim-to-proof median is now only the lead time, and the forecast falls back to the measured rate when there is no median (`ETA = now + remaining ÷ proven/h`) instead of staying `unknown`.
