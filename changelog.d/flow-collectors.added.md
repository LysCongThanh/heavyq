**`heavyq flow` sees CI waits and merge conflicts.** Two optional collectors fill the states the flow state could not derive before: `conflict_rework` from the merge commits that merged main into an item's branch and conflicted (git only, offline; the conflicted files are kept, so a hotspot file shows), and `ci_wait` and `merge_wait` from the workflow runs and pull requests gh reports (only when gh is installed and logged in; at most one call per five minutes, cached under the git common dir, failing open; `HEAVYQ_FLOW_GH=off` turns it off). The constraint finder now also needs the share to exceed the state's own EWMA baseline, so a large but normal share is no longer news; the baseline is kept in `state.json`. `run` in `state.json` is filled from the open run span. The status line and recap read the same `flow.Snapshot` types as the writer, and the forecast flags "at risk" from `throughput.last_proof`. Proven by replaying a synthetic serial-CI convoy (`TestReplaySerialCIConvoy`). See `docs/flow.md`.
